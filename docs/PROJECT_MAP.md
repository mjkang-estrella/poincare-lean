# Project Map

This map explains the repository by responsibility. It is intentionally
shorter than the proof graph.

## What Counts as Completion

The canonical endpoint is defined in `Poincare/Statement.lean`. The project is
complete only when Lean checks:

```lean
Poincare.poincare_conjecture : Poincare.PoincareConjectureStatement
```

without local placeholders or nonstandard axioms. Conditional routes,
dependency packages, and audit success are supporting evidence, not this
endpoint.

## Main Layers

| Layer | Primary surfaces | Purpose |
| --- | --- | --- |

| Work history | `harness/tasks`, `harness/reports`, `harness/ledger.json` | First-generation task attempts and reports. Historical after 2026-07-07 unless revalidated. |

## Why the Repository Feels Large

`Poincare/Global/` contains long chains of narrowly named reduction and
assembly modules. A filename often records the exact hypotheses that have
already been eliminated. Read those names from right to left:

- `...Boundary` usually states a remaining input surface;
- `...Reduction` converts a stronger input into an existing consumer;
- `...Assembly` combines already proved components;
- `...Provider` packages a universally reusable witness;
- `...Recognition` converts geometry into the sphere conclusion.

Do not start by reading all of `Poincare.lean`. Find the target declaration,
then use `rg` for its consumers and direct imports.

## Finding the Active Frontier

Use evidence in this order:

1. Read `HANDOFF.md` and note its date and commit.
2. Inspect the newest commits and changed files.
3. Search the newest boundary module for the exact missing hypothesis type.
4. Check its direct consumers and predecessor theorems with `rg`.
5. Run a focused Lean probe before writing a task.
6. Record the task against an exact base commit.

The legacy ledger's last task can be useful historical context, but it must not
be dispatched unchanged after a later bulk import or proof checkpoint.

## Status Surfaces

- `CURRENT_STATUS.md` is generated by `scripts/write_status_summary.sh`. Its
  timestamp is part of the data. Regeneration runs a full build and all audits.
- `RESEARCHER_VERIFICATION.md` is a long evidence log. Use search, not linear
  reading.
- `DEPENDENCY_LEDGER.md`, `MATHLIB_GAP_ANALYSIS.md`, and
  `EXTERNAL_RESEARCH_STATUS.md` explain external or package-level gaps.
- `harness/reports/*_blocked.md` often preserves an exact Lean type that can be
  turned into the next bounded task.

## Recommended Working Loop

1. Select one exact missing shape.
2. Create a branch/worktree from a recorded commit.
3. Inspect the smallest import closure that owns the shape.
4. Prove or reduce it in a narrowly scoped file.
5. Run focused elaboration and hygiene checks.
6. Have the orchestrator independently review and gate the diff.
7. Integrate serially, then run root checks.
8. Update the task record and handoff with evidence.

The planned automation for this loop is in `harness/v2/SPEC.md`.
